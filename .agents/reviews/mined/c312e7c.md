## Reading

This is a direct, reproduced false-green: the prior commit's fix (d2090dd) claimed to remove the unchecked assumption underlying every documented capability-size figure, but its pin tested the wrong thing — the length returned by a *function*, justified only by a parenthetical comment asserting (without checking) that the function was the only `nonce_fn` the production issuer ever installs. The review's rejection was verified by literally reintroducing the original 16-byte defect at the one call site that matters and observing the full workspace test suite stay at exactly the same passing count, byte-identical to green. The commit's own conclusion — "the ticket's own diagnosis... was still true after the commit that claimed to fix it" — states plainly that the original defect (nothing compares the assumed nonce length against the issuer that produces it) was still present after a commit whose entire purpose was to close it.
