## Reading

Two separate defects surface in this one commit. The main one is a live,
security-relevant fail-open in the kick relay shipped in a374720: a `biased`
`select!` polling order meant a revocation could be evaluated against a
kick-target map not yet armed by a queued CONNECT advisory, silently kicking
nobody roughly 3 times in 8 under the measured backlog conditions — this was
caught by the implementer's own repeated live measurement, not a named
outside reviewer, and the commit is honest that this is exactly the kind of
false-green class the project has been burned by before. The second is a
sharp, self-contained correction: an earlier commit message (5a16482) claimed
the live S9 test proved the production revoke code path was exercised
end-to-end, and a plain grep shows the test never touches that crate at all —
it calls a helper-side function directly. The implementer chose to record the
correction in a new commit rather than rewrite the earlier message, which is
why it appears here as an explicit retraction of a specific prior claim.
