## Reading

The ticket that drove this commit (td-c9b9bd) was written around the already-visible symptom — a failed `ROLLBACK` leaving the shared `Audit`/`Store` connection stranded inside an open transaction — but the implementer's own audit of the surrounding code found a second, symmetric hole on the COMMIT success path that had shipped silently: a failed `COMMIT` also stranded the connection, with no rollback attempt and, unlike the named path, no log line at all. This is exactly the "invariant enforced in one place and not its sibling" shape: the diagnostic added by an earlier commit (5f0fa3a) for the ROLLBACK-failure case gave the illusion the failure mode was covered, while the COMMIT-failure case remained both broken and invisible until this audit unified both branches through one recovery path.
