## What the commit says

> `add_share` got an `Immediate` transaction in 370fbec. An adversarial review
> of that fix found the identical unguarded defect one function away, plus a
> test that was passing for the wrong reason.
>
> `add_share_exclude` read `SELECT COUNT(*) FROM share_excludes`, compared it
> to `max_excludes_per_share`, then inserted — three separate autocommits. Two
> concurrent callers adding *distinct* globs both read the same stale
> under-cap count and both inserted, carrying the share past the cap.
> `INSERT OR IGNORE` does not cover this: it suppresses a duplicate glob, not
> a concurrent distinct one, and no SQL constraint can express "at most N rows
> per share_id".
>
> Also fixes `concurrent_add_share_cannot_persist_overlapping_roots`, whose
> assertions were unreachable on the failure path. `Store::open` runs
> `check_persisted_share_overlaps`, so on a genuine race the reopen returned
> `PersistedSharesOverlap` and `.expect("reopen")` panicked before either
> assertion ran — an unrelated pre-existing safety net, not this test's own
> invariant, was what reported the failure. The invariant is now asserted
> before the reopen.

## Reading

An adversarial review of the previous concurrency fix (370fbec, which
transaction-wrapped `add_share`) found the identical check-then-act race
still present one function away in `add_share_exclude` — the same
`missing-guard` shape, where an invariant was closed in one place and left
open in its sibling. The same review also found that an existing regression
test for the *first* fix was passing for the wrong reason: its own two
assertions were unreachable, because an unrelated pre-existing safety net
(`Store::open`'s overlap check, triggering a `.expect("reopen")` panic)
fired first and reported the failure before the test's own invariant could
be checked. That is a concrete `unverified-coverage-claim` — the test
appeared to verify the property it was named for, but a mutation targeting
that exact property was never actually observed by its own assertions.
