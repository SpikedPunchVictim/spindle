## Reading

This commit found a real, high-severity credential leak already present in shipped code: an alternate CLI flag syntax (`--flag=value`) that every other CLI users might reasonably try, but that spindle-helper's space-separated parser does not accept, fell through to an error path that echoed the full raw token — including a live nkey signing seed — straight into an `error!` log line. This was discovered by extending the existing redaction audit past what its automated guard tool can see: the guard inspects tracing call-site binding names, but this leak (and the two others in the same commit) surfaced only through an error type's own `Display` implementation, a class the guard cannot detect by construction. The commit is candid that this gap in the guard's own reach (td-a196b6) remains open. Despite applying its own lesson within the commit ("when a safety argument enumerates N disqualifying properties, every cleared item needs N answers") to find leak 3, a follow-up adversarial review (a337c18) found the commit's own citation of where the credential leak surfaced was itself wrong, and that a whole error variant (`SignalingError::Ice`) had been left completely unaudited.
