## What the commit says

> `68ae944` inserted three lines into DESIGN.md's §A4b edge-rules bullet (the
> "a fold collision between different kinds of entry is refused, never
> overwritten" decision). That pushed the case/Unicode-fold overwrite rule
> from lines 370-371 to 372-373, and left six code comments citing a range
> that now points at the browse/upload/delete edge rules instead.
>
> The rule these comments mean — "creating a name that collides
> case-insensitively or under Unicode normalization with an existing dirent
> **is** an overwrite" — is the identity rule SCHEMA_V7 and fold_key exist to
> implement, so a citation that silently drifts off it is exactly the kind of
> reference that lets a future reader re-derive the rule from the wrong text.
>
> Comment-only; found by the reference audit on td-2db67d.

## Reading

A design-doc edit two commits earlier (68ae944) shifted a line range by two lines, and six otherwise-unrelated code comments that cited that range by absolute line number silently started pointing at the wrong rule. This is a small, low-severity but mechanically clean instance of the stale-line-citation defect class: nothing was functionally broken, but a future reader following any of the six citations would land on the wrong paragraph of DESIGN.md and could re-derive an incorrect rule. It was caught by a dedicated "reference audit" pass tied to the td-2db67d ticket rather than by ordinary testing, since a wrong line-number citation in a comment has no way to fail a test suite.
