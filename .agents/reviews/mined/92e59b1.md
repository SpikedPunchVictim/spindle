## Reading

This is a pure prose-correction commit following an adversarial review of the two prior code commits (0306dea, 21723f7) — the code itself was cleared as correct, but four separate claims made in comments and, critically, in a prior commit message (0306dea) were found wrong. The most structurally interesting finding (F4) is a grep that could not see the dominant idiom it was counting: 0306dea searched for `unchecked_transaction|.transaction()` and concluded there were three transaction sites and that the two-argument pattern was "house style," when the actual dominant pattern (`Transaction::new_unchecked(...)`, six occurrences) used a name the search pattern structurally could not match. The conclusion happened to survive, but the supporting count and the "house style" framing were fabricated by an incomplete search — the same failure mode this repo's own working notes elsewhere name as "dependency guards defeat repo-only greps." F1 and F3 both show a security-relevant rationale being restated slightly wrong in follow-on prose, including one case (F3) where the doc for the *safe* accessor still recommended the *vulnerable* sequence after the fix had shipped.
