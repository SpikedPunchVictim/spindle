## What the commit says

> Running it for real caught 12 pre-existing leaks in `spindle-helper`'s
> binary — `%host_fp`, seven `%target.nats_fp`, `%delta.host_fp`, and a
> `?fingerprints` vector of full fingerprint strings. All now `.redacted()`,
> with the one genuinely-safe case annotated. Shipping the tool while leaving
> the leaks it detects would have been the wrong trade.

## Reading

While building a new redaction guard as step 1 of a broader tracing-adoption effort, the implementer ran the new tool against spindle-helper's existing (already-shipped) tracing call sites and found 12 places where full, untruncated fingerprints — including a host fingerprint, seven target NATS fingerprints, and a vector of complete fingerprint strings — were already being logged in plaintext, in direct tension with DESIGN.md:850's no-payload-logging rule and the system's stated zero-knowledge posture. This is filed because it is a concrete instance of the implementer's own audit (running a self-built detection tool against the live codebase) surfacing defects that had already shipped, rather than something caught by ordinary compilation or the existing test suite — a static/behavioral property like "this logs an identifier" has no natural test failure mode without a purpose-built detector.
