## Reading

Both reviewers approved dc775b6's core security mechanism (one independently re-derived every golden vector with an outside implementation, a strong form of verification), but between them raised six lower-severity findings, all real: an incomplete enumeration comment that had already propagated into DESIGN.md itself two commits earlier; a test that asserted a weaker property (tag distinctness) than the one that actually matters for security (prefix-freeness, since the signing input has no length prefix separating tag from payload); two overstated code comments crediting the wrong mechanism for a guarantee; a TypeScript vacuous-equality gap recurring a third time in the same defect family first found in 19dc41e; and a test-file typechecking gap that let three stale field literals survive undetected. None of these were independently exploitable, but each represents a claim (a comment, a test name, a description of a safety margin) that was more confident than what the code actually established — the same pattern this whole review lineage keeps surfacing at decreasing severity.
