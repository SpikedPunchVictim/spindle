## What the commit says

> `device_fp = H(DEVICE_FP_DOMAIN, alg_id, sign_pk, agree_pk)`, which makes a
> stored device key pair self-verifying... That property only holds where
> something actually rehashes them. The connect path did. The upload-manifest
> path did not — it fetched `sign_pk` alone via `Store::device_sign_pk` and
> verified a manifest signature under it, never checking the key belonged to
> the device.
>
> Rather than add a second copy of the rule, both paths now share one...
> Two copies of this rule is what produced the bug — the connect path grew the
> check, the request path did not, and the divergence survived until an
> adversarial review found it.
>
> Three coverage gaps found by neutering, all closed here rather than filed:
>
> - The `BindingMismatch`-vs-`Unverifiable` routing distinction had no test.
>   Collapsing the two arms left the whole suite green.
> - The device lookup in `verify_manifest_signature` had no test. Replacing it
>   with `member.devices.first()` — verifying against whatever device is first
>   on the member, ignoring `device_fp` — left the whole suite green...
> - That second gap surfaced an undocumented load-bearing property: the row and
>   the fingerprint are passed to the helper separately, so a wrong-device
>   lookup degrades to `BindingMismatch`. Passing `&device.device_fp` instead
>   would compile, pass every test, and turn the check into a tautology.

## Reading

This is a clean instance of the "invariant enforced in one place and not its sibling" pattern: the device-key self-verification property (a stored key pair must actually rehash to the fingerprint naming its row) had been added to the connect-authorization path but never to the upload-manifest verification path, which instead fetched a bare signing key and trusted it unconditionally. The commit is explicit that the divergence was found by an adversarial review, and not exploitable in practice only by an accident of the current codebase (the sole writer of `sign_pk` today happens to be trusted) rather than by design — a guarantee that Stage 7's device enrollment would remove. Fixing it by extracting one shared `checked_device_keys` implementation also surfaced three coverage gaps via neutering: two places where deleting or weakening a check left the entire suite green (the error-routing distinction and the device lookup itself), and a third where the fix nearly introduced a tautological check by conflating two values that needed to stay independently sourced.
