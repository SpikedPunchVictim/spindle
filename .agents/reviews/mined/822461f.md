## Reading

Stage 4 slice 3 (3acf54f) shipped `spindle-helper`'s TURN-credential-minting
endpoint (`turn.rs`) accepting a caller-supplied `nats_fp` in the request
payload rather than deriving it from the NATS-verified subject the callout
had already granted. That let any authenticated device impersonate another
session's identity in its TURN-quota request — a quota-griefing
vulnerability against a different account's usage bucket. The design-doc
commit two commits later (202db4f) records this as one of "two
spec-vs-implementation findings from Stage 4 slice 3," explicitly naming
the closed gap as A12 #45 and pointing out the code still served the
insecure endpoint. 822461f is the actual fix: identity now comes from
`helper.turn.get.<nfp>`'s callout-granted subject, and the payload's
`nats_fp` field is removed outright rather than merely validated. The same
finding is reused as the template for a second, proactively-applied fix to
`helper.presence.get` in bd8567c before that endpoint ever shipped.
