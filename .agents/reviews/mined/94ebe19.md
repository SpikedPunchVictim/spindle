## What the commit says

> Independent review of the v0.9.32 custody amendment found it specified
> custody for a `DeviceKey` while calling it the root key. The two are
> different types, and the rule as written could not execute:
> `RootKey::from_seed` (identity.rs:61) takes ONE seed and is already the
> supported recovery-phrase constructor, not a test-only one, while
> `DeviceKey::from_seeds` (identity.rs:176) takes TWO. This workspace had
> already recorded that exact conflation as a defect — see
> spindle-test-fixtures/src/lib.rs:118-121, "the two fingerprints
> collapsed into one".
>
> Three further gaps the same review found are closed:
>
> - An absent, locked or unreadable keychain entry is now a REFUSAL TO
>   START, never an implicit first run... a host that "helpfully" generated
>   a fresh root would silently change `host_fp` and wall every member.
> - The 0600/0700 seed-file rule is POSIX-scoped. Mode bits are synthetic
>   on NTFS/SMB/NFS and on container bind mounts whose fmask hides the real
>   ACL, so a blind check would refuse a correctly-protected NAS host.
> - "The root stays cold" is defined as *certifies an operating key, never
>   signs routine traffic* — not *offline*, which A10.41's own custody
>   layer contradicts by loading it at enrollment and restore.

## Reading

The v0.9.32 DESIGN amendment (7bafbb2) specified a key-custody rule that, on inspection of the actual key-type constructors, could not be implemented as written: it named the root key but described the seed-count and derivation shape of a `DeviceKey`, a type this same workspace had already recorded confusing with the root key once before. This is a clean `spec-cannot-execute` case — not a coding bug, but a design document whose central rule did not correspond to any real code path. The review found three further gaps in the same amendment, each a case of a rule stated more generally or more absolutely than reality supports: a missing-guard around the autostart-before-keyring-unlock race, a POSIX-only permission check written as if it were universal, and an "offline" reading of "the root stays cold" that the amendment's own custody mechanism (loading the root at enrollment and restore) directly contradicts.
