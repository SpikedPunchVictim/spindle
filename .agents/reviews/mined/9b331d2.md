## Reading

This commit builds a rate limiter and timing-equalization defense for the connect path, and an adversarial review conducted before it landed found six defects that had each survived a green gate of 125 tests. The most striking is the first: a single deletable line (updating the bucket's last-refill timestamp) had no test able to detect its absence, because both existing refill tests advanced the mock clock exactly once from bucket creation — the one scenario where "measure from creation" and "measure from last refill" agree — so a limiter that would silently stop limiting within seconds of real wall-clock time still passed every test. The NaN/infinite-config fail-open bug is a second distinct security-relevant defect (a limiter is supposed to fail closed, and instead a malformed config makes it refill to full on every call). Because these defects were caught by review before the code was ever committed as a separate, already-merged change, this is filed as a "nearly shipped" case per the task's instructions rather than a fix to a named prior commit — all six were fixed in the same commit that introduces the feature, with each one neuter-verified individually.
