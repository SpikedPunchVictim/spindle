## What the commit says

> `default_member_cap_nonce` returns a 32-byte `Fingerprint`, it is the only
> `nonce_fn` `RootKeyCapIssuer` installs, and `with_nonce_fn` has no callers —
> yet every size figure DESIGN has ever stated was measured against a 16-byte
> nonce, and every fixture in the repo hardcoded that same 16. So the tests
> agreed with each other and with the document while all of them disagreed
> with the code, and a fully green gate said nothing.
>
> The consequential correction is the QR ceiling. At the 256-byte
> MAX_REGISTRY_LEN a version-40 code carries 3 hosts at EC level M, not 4:
> four real entries encode to 2365 B against a 2331 B budget, so a bundle
> built to the documented claim would have failed to encode. Nothing shipped
> broken -- build_bootstrap_bundle measures each real candidate rather than
> trusting the constant -- but the documented ceiling was wrong by one host.
> That "4" had been derived by adjusting an earlier figure by a per-entry
> delta rather than re-measured, which is the same habit that produced the
> underlying error.

## Reading

Every measured-size figure DESIGN.md had ever stated — across multiple prior version bumps — turned out to have been measured against a 16-byte nonce that no production code path ever produces; the real minting path uses a 32-byte fingerprint. Because every test fixture in the repository independently hardcoded the same wrong 16-byte value, the tests, the fixtures, and the document were all internally consistent with each other while collectively disagreeing with the code, which is exactly the shape of error a fully-green test suite cannot surface on its own. The QR-ceiling correction is the most consequential instance: a previous figure had been derived by adjusting an earlier number with a computed per-entry delta rather than by direct re-measurement, and the commit calls that out explicitly as "the same habit that produced the underlying error" — meaning the QR ceiling had drifted from reality twice via the same shortcut. This is the opening commit of a long chain (continuing through c312e7c, 1072ba5, and 38191de) where successive independent reviews kept finding that the "fix" for this class of defect had not actually closed it.
