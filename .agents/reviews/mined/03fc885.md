## Reading

While adding the device_fp-recompute check to certificate verification, the first three tests written to cover it were constructed so that a completely different, pre-existing check (the signature check) would already reject the mutated inputs — meaning the tests would pass identically whether or not the new recompute check existed at all. The commit says this was "caught in review, not by the suite," explicitly distinguishing it from a test-run failure. It's ambiguous whether these three tests ever existed in a committed state before being fixed within this same commit, so I've marked `introduced_by` unknown rather than guessing. The fix — an isolating test built from a hand-signed, internally-inconsistent certificate that only the recompute check can catch — and its mutation verification are the load-bearing evidence that the gap was real and is now closed.
