## What the commit says

> Two real bugs only a live server could catch, both fixed:
> 1. $SYS.ACCOUNT.*.CONNECT|DISCONNECT are ordinary SYS-account pub/sub
>    broadcasts — unlike $SYS.REQ.USER.AUTH / $SYS.REQ.SERVER.PING.CONNZ,
>    which nats-server special-cases for any auth_callout responder. The
>    callout user lives in the AUTH account, so the event subscriptions
>    silently received nothing. Fix: dedicated SYS_CONN_USER nkey in the
>    SYS account (deploy conf + SYS_CONN_SEED env + third helper
>    connection). NOTE: DESIGN §A5's two-connection bridging [DEFAULT]
>    needs amending — helper is now three connections.
> 2. CONNZ replies carry no identity unless requested with {"auth":true},
>    and the field is "authorized_user", not "user". Parser fixed
>    (tolerant of both) + 6 bin unit tests using real captured payloads.

And, from the immediately preceding commit ac9bb98, the implementer's own
advance caveat about what shipped un-verified:

> $SYS payload shapes are modeled tolerantly but NOT verified against a
> live server — S5 validates.

## Reading

The presence feature (ac9bb98) shipped subscribing to `$SYS.ACCOUNT.*`
broadcasts on the helper's existing AUTH-account connection, on the
assumption that the same cross-account special-casing nats-server grants
`$SYS.REQ.USER.AUTH` and `$SYS.REQ.SERVER.PING.CONNZ` would also let that
connection see ordinary SYS-account broadcasts. That assumption was false
in a way that failed silently — no error, just an event stream that never
fired — and DESIGN's two-connection helper-bridging model, carried since
S1's d80d070 ("the helper's two-connection [DEFAULT] is confirmed
necessary"), had to be revised to three connections once S5 ran presence
against a live server. Separately, the $SYS/CONNZ payload-shape parsing in
the same commit was explicitly flagged by its own author as unverified
against a live server, and the live run of S5 found the field name and the
`{"auth":true}` requirement were both guessed wrong. Both are the
implementer's own live-server audit catching defects in code that had
already shipped one commit earlier, not an outside reviewer's finding; the
account-bridging fix was then folded back into the design doc in the
following commit, a9820e8 ("S5's live evidence falsifies the two-connection
bridging model this doc carried since S1").
