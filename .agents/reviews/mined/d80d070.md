## Reading

While wiring spindle-helper's already-shipped pure authz core (from commit
16146ba, built on spindle-core's `issue_capability` from e1053f4) to a live
NATS auth-callout loop, the implementer found that two sibling code paths —
device-side subject scoping and host-side subject scoping — computed a
capability's `host_fp` two different ways, and the values silently diverge
whenever the signing (operating) key differs from the root key. This is
exactly the missing-guard shape: an invariant (one true host_fp per
capability) was enforced correctly on one side and not its sibling, and it
shipped in Stage 3/4 code before anyone exercised a root-vs-op-key mismatch
case. The commit explicitly declines to fix it in place, flagging it as
requiring a design decision before Stage 4 wiring proceeds — which is what
happened three commits later in dcdd6e5 (A10.30, capabilities carry the
full host key chain).
